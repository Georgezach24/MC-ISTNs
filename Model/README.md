# Model — Part 2 proof-of-concept

Supervised-classification pass on top of the Part 1 simulation. It predicts `ServingType` (Terrestrial vs Satellite) per user from **candidate-level** features, and measures how much of that decision survives when the unrealistic assumption of perfect instantaneous SNR knowledge is removed.

`Model/` only ever consumes `Dataset/dataset.csv`; it never changes simulation logic in `PROD/`.

## Dataset

Generated by `PROD/monteCarloDriver.m`:

```matlab
monteCarloDriver(3000)      % rng(42) -> Dataset/dataset.csv
```

Current dataset: **3,000 scenarios / 19,385 user rows**.

| Serving node | Rows | Share |  | Service state | Rows | Share |
|---|---:|---:|---|---|---:|---:|
| Satellite | 13,129 | 67.7% |  | Served | 16,433 | 84.8% |
| Terrestrial | 5,822 | 30.0% |  | BelowTarget | 2,518 | 13.0% |
| Outage | 434 | 2.2% |  | Outage | 434 | 2.2% |

Rows excluded before training: 434 `Outage` (the question "which of the two nodes wins" presupposes a choice) and 51 with `BsUnavailReason = "OutOfModelRange"` (no terrestrial candidate was computed because the link falls outside the UMa/UMi validity range — a simulation limitation, not a physical state). Remaining population: **18,904 rows, majority class 69.20%**.

## Label sanity check (do this before reading any accuracy number)

The labeling rule is applied directly to the raw candidate SNRs, including the visibility mask and the minimum-usable-SNR floor, and compared against the recorded label:

```
SNR_min = -7.5346 dB
deterministic rule reproduces label: 100.0000% of 19385 rows (0 mismatches)
```

So the target is, by construction, a deterministic function of two input features. Any model given the exact SNRs must approach 100%; that variant is a **pipeline correctness check, not a prediction result**.

## Three variants

All three share: candidate-level features only (never the winning node's own metrics), `NodeLoad` excluded (it is a consequence of the label for the whole scenario), train/test split **by `ScenarioID`** via `GroupShuffleSplit` 75/25 (2,250/750 scenarios, 4,843 test rows), Logistic Regression + Random Forest (300 trees, depth 12).

| Script | Feature information | What it is for |
|---|---|---|
| `train_model.py` | exact `CandBS_SNR_dB` / `CandSat_SNR_dB` | correctness check of the MATLAB → CSV → Python chain |
| `train_model_noisy_snr.py` | SNR + Gaussian noise (σ from `Results/kpi_summary_by_type.csv`: 17.17 dB terrestrial, 1.79 dB satellite) | imperfect/stale measurement |
| `train_model_geometry_only.py` | no SNR **and** no path loss (near-affine proxy) | lower bound: what geometry alone carries |

## Results (3,000-scenario dataset, `rng(42)`)

| Input features | LR accuracy | LR ROC-AUC | RF accuracy | RF ROC-AUC |
|---|---:|---:|---:|---:|
| Exact SNR (check only) | 0.9971 | 1.0000 | 0.9930 | 0.9998 |
| Noisy SNR | 0.8654 | 0.9248 | 0.8635 | 0.9214 |
| Geometry only | 0.8102 | 0.8584 | 0.8121 | 0.8566 |
| Majority class | — | — | 0.6920 | — |

Both classifiers land within ~0.2 points of each other once the exact SNR is removed, so these runs do **not** support a claim that the problem needs a non-linear model. The meaningful comparison is each classifier against the majority-class baseline.

## Feature importance

Each script now writes both impurity-based and permutation importances (10 repeats, held-out set) into `metrics.json`:

| Variant | Top features (impurity / permutation) |
|---|---|
| Exact SNR | `CandBS_SNR_dB` 0.352 / 0.235 · `CandBS_PathLoss_dB` 0.227 / 0.090 · `CandSat_PathLoss_dB` 0.139 / 0.076 · `CandSat_SNR_dB` 0.136 / 0.071 |
| Noisy SNR | `CandBS_Distance_m` 0.361 / 0.130 · `CandSat_SNR_noisy_dB` 0.247 / 0.084 · `CandBS_SNR_noisy_dB` 0.157 / 0.033 |
| Geometry only | `CandBS_Distance_m` 0.518 / 0.153 · `CandSat_SlantRange_m` 0.180 / 0.012 · `CandSat_Elevation_deg` 0.177 / 0.015 |

Two caveats belong with any reading of this: SNR and path loss of the same link are near-affine (fixed EIRP and noise floor), so their combined importance describes **one** quantity split arbitrarily between two columns; and impurity importance is biased toward features with many split points, which is why permutation importance on the test set is reported alongside.

## Running

```
pip install -r requirements.txt
python train_model.py
python train_model_noisy_snr.py
python train_model_geometry_only.py
```

Requires `Dataset/dataset.csv` (generate it first in MATLAB) and, for the noisy variant, `Results/kpi_summary_by_type.csv` from `kpiRepeatedRuns.m`. Outputs land in `results/`, `results_noisy_snr/`, `results_geometry_only/` (metrics JSON + confusion matrices + ROC + importance plots).

`MIN_ELEVATION_DEG` in all three scripts must match `satParameters.MinElevationDeg` in the simulation (currently 20°); it is used only to derive the `CandSat_Visible` flag.

## What this does not show

The target is the decision of the simulation's own rule, not a network outcome. Nothing here demonstrates that a learned decision improves throughput, availability or energy — that requires evaluating the model's decisions against the reference rule on those metrics. The dataset is also a set of independent snapshots with no temporal dimension, so it cannot support claims about predicting a transition before it happens. Both are the next steps.
